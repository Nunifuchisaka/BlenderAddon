# 統計/書き出し前チェック機能: コレクション構成チェック 設計

## 背景・目的

`diagnostics` featureは既に「アバターコレクション」1つを指定してポリゴン数・マテリアル数・ボーン数などの統計と、頂点座標/スケール/回転/非多様体エッジ等の書き出し前チェックを提供している。

このアドオンは第三者へ配布するため、購入者がどのようなコレクション構成（フラットに1コレクションへ全部まとめる/体・衣装・Accessory等でサブコレクションに分ける等）を採用しているかは制御できない。一方で、サブコレクション運用をしているユーザーには「分類し忘れて直下に置いたままのメッシュ」「書き出し対象のつもりが除外/非表示コレクションに紛れて漏れているオブジェクト」「同じオブジェクトを複数のサブコレクションへ重複してリンクしてしまっている」といった、構成上のミスに気づきにくいという課題がある。

これを解消するため、`avatar_collection` 配下のサブコレクション構成を機械的に走査し、構成ミスの可能性を検出するチェックを `diagnostics` に追加する。

### 設計方針（重要な前提）

配布先の運用が不明なため、**特定の分類名（アバター/衣装/Accessory等）を前提にした固定スキーマは採用しない**。子コレクションが「何のカテゴリか」を判定・要求することはせず、コレクション階層構造そのものから機械的に判定できる異常のみを検出する（案A）。「衣装カテゴリには最低1メッシュ必要」のような、カテゴリ名を前提にした必須要素チェックは対象外とする。

**既存のフラット構成（サブコレクションを一切使わない、現状の主要な使い方）を誤検知しないこと**を最優先の制約とする。サブコレクションを使っている形跡がない場合、新規チェックは実質的に何も警告を出さない。

## 機能概要

既存の「診断を実行」（`OBJECT_OT_amt_diagnostics_run`）が出力する「--- 書き出し前チェック ---」セクションに、以下の項目を追加する。UI・プロパティの追加は無い。

| チェック内容 | 重要度 | 適用範囲 |
|---|---|---|
| 子コレクションを介さず直接配置されたメッシュ | WARNING | `avatar_collection`直下のみ。かつ子コレクションが1つ以上存在する場合のみ判定（完全フラット構成ではスキップ） |
| 除外(Exclude)または非表示(hide_render)のコレクションに中身がある | WARNING | 全階層。ただし該当ブランチの子孫は打ち切り（1ブランチ1警告） |
| オブジェクトが複数の子コレクションへ重複所属 | WARNING | 全階層 |
| コレクション名が既定値のまま（`Collection`, `Collection.001`等） | INFO | 全階層 |
| アーマチュアが0個、または2個以上 | WARNING | `avatar_collection`全体 |
| 中身が空のサブコレクション | INFO | 全階層 |

## アーキテクチャ

既存の `features/diagnostics/` の4ファイル構成を維持する。新規featureや新規プロパティは追加しない。

### `utils.py` に追加する純ロジック関数

- `walk_collection_tree(collection)` — `collection.children` を深さ優先で再帰的に辿り、`(child_collection, path)` のペアをyieldするジェネレータ。`path` は表示用の `"衣装/シャツ"` 形式の文字列（親からのコレクション名を`/`で連結）。
- `find_uncategorized_mesh_objects(collection)` — `collection.children` が空なら `[]` を返す。1つ以上あれば、`collection.objects` に直接リンクされた `type == 'MESH'` のオブジェクトを返す（`ARMATURE`は対象外。体・衣装を跨いで最上位に置かれるのが一般的なため）。
- `find_layer_collection(layer_collection, target)` — `context.view_layer.layer_collection` を根として再帰探索し、`target`（Collectionデータブロック）に対応する`LayerCollection`ノードを返す。見つからなければ`None`。
- `find_excluded_or_hidden_branches(collection, layer_collection_root)` — `walk_collection_tree`で全階層を辿りつつ、各ノードについて「`find_layer_collection`で見つかった対応ノードの`.exclude`が`True`」または「`collection.hide_render`が`True`」を判定する。該当した時点でそのブランチの配下には再帰しない（1ブランチにつき1件、`(path, collection, reason)`のリストを返す）。`find_layer_collection`が対応ノードを見つけられない場合はexclude判定をスキップし、`hide_render`のみで判定する。
- `find_duplicate_membership(collection)` — `walk_collection_tree`で辿る全ての子コレクション（`avatar_collection`自身は含めない）について、`.objects`（直接所属、非再帰）を集計し、2つ以上のコレクションに直接所属しているオブジェクトを `{object: [path, ...]}` の形で返す。
- `find_default_named_collections(collection)` — `walk_collection_tree`で全階層を辿り、`re.fullmatch(r"Collection(\.\d+)?", child.name)` にマッチするものを `(path, collection)` のリストで返す。
- `find_empty_collections(collection)` — `walk_collection_tree`で全階層を辿り、`len(child.all_objects) == 0` のものを `(path, collection)` のリストで返す。

いずれも `bpy.types` のクラスを新規定義しない（`Collection`/`LayerCollection`はBlender組み込み型を引数として受け取るのみ）。

### `operators.py` — `OBJECT_OT_amt_diagnostics_run.execute` への追加

既存の統計セクション（ボーン数表示の直後）に、アーマチュア0個/2個以上の警告を追加する:

```python
if len(armature_objs) == 0:
    lines.append(('WARNING', "アーマチュアオブジェクトが見つかりません"))
elif len(armature_objs) >= 2:
    lines.append(('WARNING', f"アーマチュアオブジェクトが{len(armature_objs)}個あります(通常は1つを想定した機能です)"))
```

既存の「--- 書き出し前チェック ---」セクション、既存のオブジェクト単位ループ（NaN/スケール/回転/非多様体）の後ろに、コレクション構成チェックのブロックを追加する。`collection = props.avatar_collection` と `context.view_layer.layer_collection` を使って上記 `utils` 関数を順に呼び出し、結果をレポート行へ変換する。

各項目のレポート文言例:

- `f"[{obj.name}] コレクション直下に直接配置されています(サブコレクションへの分類漏れの可能性があります)"`
- `f"[{path}] {reason}のコレクションですが、中に{count}個のオブジェクトがあります(書き出し対象から漏れる、または意図せず含まれる可能性があります)"`（`reason`は「除外」または「非表示」）
- `f"[{obj.name}] 複数のコレクションに重複して所属しています: {', '.join(paths)}"`
- `f"[{path}] コレクション名が初期値のままです(分類名の付け忘れの可能性があります)"`
- `f"[{path}] 空のコレクションです(中身がありません)"`

いずれも `set_report_lines` に渡す既存の `lines` リストへ追記するのみで、既存の関数シグネチャ・戻り値の型は変更しない。

### `panel.py`

変更なし。既存の `report_lines` テンプレートリスト表示がそのまま新規レポート行にも対応する。

## エラーハンドリング・エッジケース

- `avatar_collection`に子コレクションが1つも無い（完全フラット構成）→ 「直接配置メッシュ」チェックは何も返さない。他のチェック（重複/デフォルト名/空コレクション/除外/非表示）も、対象となる子コレクションが存在しないため自然に空の結果となる。
- `find_layer_collection`が対象コレクションを現在のビューレイヤーの階層内に見つけられない（他シーンからのみリンクされている等）→ そのコレクションについてはexclude判定を行わず、`hide_render`のみで判定する（誤検知よりも判定不能を優先し、"問題なし"寄りに倒す）。
- 除外/非表示ブランチの配下にさらに除外/非表示のコレクションがある → 最上位のみ報告し、子孫は打ち切る（同一構成に対する重複警告を防ぐ）。ただし重複所属/デフォルト名/空コレクションのチェックは、除外/非表示ブランチの内部にも独立して適用される（除外されているからといって、その中身の構成ミスまで無視すべきではないため）。
- `mesh_objs`が空の場合は既存の早期リターン（`props.report_lines`にWARNINGを1行出して`{'CANCELLED'}`）がそのまま先に発生するため、新規チェックはこのケースに到達しない。

## テスト方針

自動テストは無し（プロジェクト全体方針）。Blender実機で以下を確認する:

1. 完全フラット構成（子コレクション無し）で新規の警告が一切出ないこと。
2. サブコレクションあり構成で、意図的に作った次のケースがそれぞれ検出されること: 直下への直接配置、除外コレクション、非表示コレクション、重複所属、デフォルト名のまま、空コレクション。
3. 除外コレクションの内側にさらに除外コレクションがある2段構成で、警告が1件のみ（最上位のみ）出ること。
4. アーマチュアオブジェクトが0個、および2個の状態でそれぞれ警告が出ること。

## スコープ外

- コレクション名からカテゴリ（アバター/衣装/Accessory等）を推定・要求する処理は行わない。
- 検出した構成ミスの自動修正（コレクションの移動・リンク解除等）は行わない。あくまでレポート表示のみで、既存のポリシー（削除系操作のみ確認ダイアログを要する）通り、本チェックは非破壊のため確認ダイアログも不要。
- 新規プロパティ・UI要素の追加は行わない。
